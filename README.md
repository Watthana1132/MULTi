# MULTI-TASKS 0.2.0 — Pink Workflow

แอป Android ของ Watthana สำหรับทำ QA และบันทึกเติมสินค้าแบบต่อเนื่อง ปรับตาม [รายละเอียดที่แชร์](https://chatgpt.com/share/6ac14821-8d5c-83ec-b711-6580ed5dcbda)

## เปิดและรัน

1. แตกไฟล์ ZIP รุ่น 0.2 แล้วเปิดโฟลเดอร์ `MULTI-TASKS` ที่มี `settings.gradle` ใน Android Studio
2. ตั้ง Gradle JDK เป็น **JDK 21**; หากใช้ JDK ที่มากับ Android Studio แล้วพบปัญหา ให้เลือก JDK 21
3. ใช้ Android SDK 36 และรอ Gradle Sync ครั้งแรกต้องใช้อินเทอร์เน็ต
4. SDK ในเครื่องนี้คือ `C:/Users/boxgi/AppData/Local/Android/Sdk` ไฟล์ ZIP ไม่แนบ `local.properties` เพื่อให้ Android Studio ตั้ง SDK ตามเครื่องที่เปิด
5. เลือก Android 8.0+ หรือ Emulator แล้วกด Run และอนุญาตกล้อง

APK ที่ส่งเป็น **Debug APK** สำหรับทดลอง ไม่ใช่ไฟล์เซ็นสำหรับ Play Store

## ติดตั้งทับรุ่นเดิม

ใช้ applicationId เดิม `com.multitasks.store`, versionCode 2 และเพิ่ม schema ฐานข้อมูลจาก 1 เป็น 2 โดยไม่ลบตารางเดิม

- ติดตั้งทับได้เมื่อ APK เดิมและใหม่ใช้ signing key เดียวกัน
- อย่าถอนแอปเดิมเพื่อแก้ปัญหา signature หากยังต้องการข้อมูลเดิม ให้ใช้ signing key เดิมในการ build แทน
- ID, จำนวน, รูป STOCK, โน้ต, สถานะเสร็จแล้ว และวันที่เดิมยังอยู่
- QA เก่ามีป้าย **วันหมดอายุจากรุ่นเดิม**; ไม่เปลี่ยนความหมายของวันที่เก่าย้อนหลัง
- QA ใหม่ใช้ **วันที่บันทึก/วันที่รอบงาน** เริ่มที่วันนี้ตามข้อกำหนดล่าสุด ไม่ใช่วันหมดอายุ
- QA เก่าที่ไม่มีภาพสินค้ายังคงไม่มีภาพ แอปใช้ไอคอนแทน และสร้างภาพบาร์โค้ดจากเลขเดิม

## วิธีใช้

### หน้าแรก

มี 4 ปุ่ม: QA, STOCK, สร้างงาน, ประวัติ ไม่มีสรุปตัวเลขหรือรายการล่าสุด แถบล่างเป็นหน้าหลัก / กล้อง / เพิ่มเติม

### QA

กด QA แล้วกล้องเปิดทันที → อ่านบาร์โค้ดอัตโนมัติ → ตรวจเลขและภาพ → จำนวน → บันทึก → สแกนถัดไปในหน้าเดิม

- อ่านรหัสตรงกัน 2 เฟรมก่อนรับผล และเก็บภาพจากเฟรมเดียวกับที่อ่านรหัส
- มีภาพสินค้ากับภาพบาร์โค้ดพื้นขาวแยกกัน
- **สแกนใหม่** แทนรหัสและภาพเดิม ไม่ถามยืนยัน ไม่ล้างจำนวนหรือรอบงาน
- จำนวนเริ่มที่ 1, กด +/- หรือกดค้าง หรือแตะเลขเพื่อพิมพ์
- บันทึกแล้วจำนวนกลับเป็น 1 เว้นแต่เปิด **จำจำนวนล่าสุด** ในเพิ่มเติม
- วันและ session คงเดิมระหว่างงาน; หลังบันทึก รหัสเดิมจะไม่ถูกอ่านซ้ำทันทีจนกว่าจะออกจากกรอบ หรือกดสแกนใหม่
- ถ้าต้องทำวันที่อื่น ให้สร้างงานเลือกวันที่ก่อนเริ่ม หรือแก้วันที่จากรายละเอียดในประวัติ
- ไม่สร้างหรือบันทึกชื่อสินค้าอัตโนมัติ ไม่บังคับฟอร์มเพิ่มนอกเหนือจากวันที่ บาร์โค้ด และจำนวน

### STOCK

กด STOCK → ถ่ายรูป → จำนวน → บันทึก → ถ่ายต่อ

ถ่ายใหม่ได้ในหน้าเดิม มีโน้ตเสริมที่ซ่อนไว้หลังปุ่มเพิ่มโน้ต เช่น 200g / ห่อใหญ่ ไม่มีขั้นตอนบาร์โค้ด

### ประวัติและรูปภาพ

- แท็บทั้งหมด / QA / STOCK; ค้นหาบาร์โค้ดหรือโน้ต; กรองวันเริ่ม–วันสิ้นสุด; เลือกรอบงาน
- สลับรายการกับแกลเลอรี กลุ่มตามวันที่ มีป้ายจำนวนและภาพบาร์โค้ดย่อ
- เลือกหลายรายการหรือเลือกทั้งหมดที่แสดงเพื่อย้ายไปถังขยะ
- แตะรายการหรือภาพเปิด viewer ร่วม: ปัดซ้าย–ขวา, ใช้สองนิ้วซูม, ดูจำนวน/วันที่/เวลา
- เมนู viewer มีรายละเอียด แก้ไขวันที่/จำนวน/โน้ต แชร์ภาพผ่าน Android และย้ายไปถังขยะ
- QA กดไอคอนบาร์โค้ดเพื่อแสดงพื้นขาว พร้อมปรับความสว่างให้เครื่อง EOB อ่าน
- ทำเครื่องหมายงานเสร็จแล้วได้จากแผงรายละเอียด

### รอบงานและการกลับมาทำต่อ

สร้างงานใช้วันที่เป็นชื่อโฟลเดอร์โดยไม่ต้องพิมพ์ชื่อ เก็บรอบงาน QA และ STOCK แยกกัน หน้าประวัติแสดงรอบงานว่างให้เลือกได้ เมื่อออกจากกล้องแล้วเข้าเครื่องมือเดิม จะคืน draft และ session ล่าสุด การเปลี่ยน activity จะไม่ล้างผลที่กำลังยืนยัน

### สำรอง / นำเข้า / ถังขยะ

- เพิ่มเติม → สำรองข้อมูลพร้อมรูป → เลือกตำแหน่งไฟล์ ZIP ผ่าน Android
- เพิ่มเติม → นำเข้าข้อมูลสำรอง → เลือก ZIP รุ่น 0.2
- การนำเข้า **เพิ่มเป็นสำเนาใหม่** ไม่เขียนทับรายการปัจจุบัน นำเข้าไฟล์เดิมซ้ำจะมีข้อมูลซ้ำ
- สำรองรวมรอบงาน รูป บาร์โค้ด ข้อมูล และรายการในถังขยะ
- จำกัดการนำเข้า 10,000 รายการ / ข้อมูลขยายไม่เกิน 500 MB / รูปต่อไฟล์ไม่เกิน 20 MB
- การลบเป็นถังขยะ กู้คืนได้ ไม่มีการลบถาวรในรุ่นนี้
- ไม่มี Cloud หรือระบบบัญชี การล้างข้อมูล/ถอนแอปจะลบข้อมูลในเครื่อง

## โครงสร้าง

- `ui/` — Compose Material 3, theme, ปุ่มใหญ่, stepper, capture, history, gallery, image viewer, settings
- `navigation/` — Navigation Compose, ซ่อน bottom navigation ระหว่าง capture/viewer
- `viewmodel/` — StateFlow, capture state, filter state, async actions และ draft recovery
- `model/` — WorkRecord (แยก QA/STOCK ด้วย type), WorkSession, CaptureState/Transitions
- `data/` — SQLite และ migration แบบเพิ่มคอลัมน์จาก v1
- `repository/` — serializes การอ่าน/เขียนฐานข้อมูลบน Dispatchers.IO และกระจาย StateFlow
- `camera/` — CameraX + ML Kit, lifecycle binding และ exact-frame capture
- `barcode/` — ZXing สร้างบาร์โค้ดชนิดเดิมจากค่าที่สแกนได้ พร้อมตัวเลขบนพื้นขาว
- `storage/` — JPEG/PNG ภายในแอป, compression, ZIP backup/import

Kotlin 2.2.10 ผ่าน built-in Kotlin ของ AGP 9.0.1, Compose BOM 2025.04.01, Gradle 9.2.1, minSdk 26, compile/target SDK 36

ฐานข้อมูลใช้ SQLiteOpenHelper แทน Room เพื่ออัปเกรดไฟล์ SQLite เดิมตรง ๆ โดยคง ID และข้อมูลเดิมไว้ ใช้ Repository + ViewModel และทำงานฐานข้อมูล/ไฟล์นอก UI thread

## ทดสอบ

```powershell
.\gradlew.bat assembleDebug testDebugUnitTest lintDebug
.\gradlew.bat connectedDebugAndroidTest
```

ชุดทดสอบ instrumentation ต้องใช้ Emulator/อุปกรณ์ทดสอบโดยเฉพาะ เพราะเครื่องมือทดสอบอาจติดตั้งและถอนแพ็กเกจอัตโนมัติ

ดูรายละเอียดใน `TESTING.md` และข้อกำหนดที่ครอบคลุมใน `ACCEPTANCE.md`

## ข้อจำกัดที่ยังต้องตรวจหน้างาน

- ต้องทดสอบกล้องกับฉลากจริง แสงสะท้อน และเครื่อง EOB จริงก่อนใช้เป็นเครื่องมือหลัก
- ไม่มีการส่งข้อมูลเข้า EOB โดยตรง ไม่มีฐานข้อมูลชื่อสินค้า
- ยังไม่ได้ทดสอบทุกผู้ผลิตมือถือหรือทุกขนาดจอ; ข้อมูลยาวและตัวอักษรระบบใหญ่ใช้การเลื่อนหน้าจอ
- ไม่มี release keystore, Play Store listing หรือระบบอัปเดตอัตโนมัติ
- ข้อมูลตัวอย่างในภาพมาจากชุดทดสอบ ไม่ได้ฝังใน APK
